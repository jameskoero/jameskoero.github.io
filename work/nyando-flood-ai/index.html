Nyando Flood AI

Flood-susceptibility ranking for five wards of the Nyando Basin, Kenya

Status: Released (v2.0.0), live dashboard  |  Last updated: 15 Nov 2026

Problem

Rank locations in five Nyando Basin wards by flood susceptibility. The output is a ranking score, not a probability of flooding.

Requirements

  • Rank locations by susceptibility for five wards.
  • Every model must beat an elevation-only baseline, judged under rules written before any model is scored.
  • The service must verify the model file's SHA-256 before loading it.
  • Installs must be reproducible.

Data

Flood labels from Copernicus GFM across 35 Sentinel-1 scene dates: 4,420 real sampled rows, no synthetic data. Features come from Google Earth Engine and include terrain, rainfall, soil and land cover.

Architecture

  1. Copernicus GFM flood labels plus Google Earth Engine features
  2. Gradient boosting with monotonic constraints
  3. Custom ONNX exporter (numerical parity 3.3e-16)
  4. FastAPI service that verifies the model's SHA-256 before loading
  5. React dashboard

Implementation

  • Gradient boosting with monotonic constraints, chosen against logistic regression, XGBoost and a PyTorch physics-constrained neural network. The network violated the constraints, so I did not ship it.
  • Baselines in every comparison: elevation-only and a registered logistic champion.
  • Training rows at locations that appear in sealed events are removed before fitting.

Evaluation

  • Leave-one-event-out mean per-event AUC 0.943 on 23 events.
  • A sealed set of 27 events (D20), scored once. A challenger replaces the champion only if the lower end of its interval against the champion is above zero and its mean is higher.

The mappable frame is the protocol's primary analysis.

The registered model's gain over elevation alone is +0.0384 mean AUC, pooled over 50 events (95% interval +0.0193 to +0.0611; 36 wins, 9 losses). Against the champion on the full frame it gains 0.0164 AUC (interval 0.0052 to 0.0273) and wins on 19 of 27 events.

Production engineering

  • FastAPI service that verifies the model's SHA-256 before loading, with rate limiting and security headers.
  • Hash-locked Docker image (31 packages, 483 hashes).
  • GitHub Actions gates on data, manifests and README claims; CodeQL; MLflow tracking on DagsHub.
  • A deviation register that the tests enforce.
  • Release v2.0.0 archived on Zenodo.

My contribution

I designed, built, validated, deployed and documented the project as the sole developer.

Results and limitations

  • The champion's gain over elevation alone is not established: its interval includes zero on both frames.
  • No advantage was shown under a 1 km spatial buffer or an out-of-time split. The model card says so.
  • Scores rank locations. They are not calibrated probabilities.

Correction history

An earlier version reported AUC 0.9717, F1 0.9022 and cross-validation 0.9727 on 2,308 rows. A leakage audit showed the headline metric was circular. I retracted it, published an erratum on Zenodo, and rebuilt the system from real satellite data under strict leakage control.
